# OR Pricing — Power Apps code app

Port of the `ORPricingWebrescourse` model-driven web resource to a Power Apps code app.
UI, UX and business logic are the original; only the host/data plumbing changed.

## Layout

| Path | What |
| --- | --- |
| `index.html` | Original markup (inline `onclick=` → `data-onclick=` etc.) |
| `src/legacy/orPricing.css` | Original styles |
| `src/legacy/orPricing.js` | Original logic (Dataverse/Xrm calls swapped for the adapter) |
| `src/dataverse.ts` | `dvGet/dvPost/dvPatch/dvDelete` + file upload/download over the generated services |
| `src/handlerBridge.ts` | Runs `data-on*` handlers without inline script (code-app CSP) |
| `src/generated`, `.power/` | Generated by `pa app add data-source` — don't edit |

## Data sources (cross-environment)

The app is hosted in **org998df960** (env `cd78a59b-e16f-e4aa-b0a1-8e450a70ed56`), but its tables
live in **org319b4ea9** (`DATA_ORG_URL` in `src/dataverse.ts`). Per-table services (`--table`) always
hit the app's home environment, so the app uses one generic connector instead:

```bash
pa app add data-source --connector shared_commondataserviceforapps --connection-id <id> --as action
```

`src/dataverse.ts` maps `dvGet/dvPost/dvPatch/dvDelete`, lookups and file columns onto
`MicrosoftDataverseService.*WithOrganization`. `$expand` is passed straight through. Reads without
`$top` follow the connector's nested nextLink. The current user is resolved in the data environment
by Entra object id, because systemuser ids differ per environment. A new table works without setup;
add it to `PRIMARY_KEYS` only if its key isn't `<logicalname>id`.

Users need a security role on these tables in **org319b4ea9**; access to the app alone isn't enough.

## Run / deploy

```bash
npm run build
pa app run
pa app push
```

## Environment requirement

"Fetch from DotCare" calls the Power Automate HTTP trigger (`FLOW_URL`) directly. The code-app
CSP default is `connect-src 'none'`, so an environment admin must add
`https://*.environment.api.powerplatform.com` to **connect-src** (Power Platform admin center →
Environment → Settings → Privacy + Security → Content security policy → App).
